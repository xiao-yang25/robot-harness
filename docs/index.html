Two skills. One continuous scene.

An ACT policy moves the cube between the arms. Runtime keeps the scene, returns a fresh observation and admits a separate hold using the last executed target. Each operation delivers its result and settles through Core.

A deterministic caller chooses both skills. This is a recorded simulation, not autonomous task planning or a physical robot. The same-run evaluator confirms the bounded one-second hold; one seed does not establish reliability.

Built toward a broader loop.

Agents choose intent. Skills act. The world returns evidence. Robot Harness aims to connect these steps across navigation, manipulation and learned behaviors.

Task strategy and learning belong with callers; native robot stacks retain control and device protection.

Explore the architecture ↗

Grounded in what runs today.

Execution authority, guarded results, local workers, dependent tasks and limited Host recovery. Nav2 simulation covers sequential navigation, moving cancellation, replacement and bounded loss isolation. The optional Python Runtime runs a MuJoCo/ACT skill and continuous transfer-to-hold operations; local MCP tools let existing agents consume the session.

Early-stage software and simulation: no physical-robot integration or hard stop guarantee. A separate embodied business Agent, broader learning backends and self-improvement remain planned work.
